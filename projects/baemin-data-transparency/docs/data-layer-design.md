# 데이터 레이어 분리 설계 (T013)

## 목적

원본 파일부터 분석 결과까지 4단계 레이어로 분리하여 재처리 가능하게 설계한다.

## 1. 레이어 개요

```
Layer 0: Raw       → 사장님이 업로드한 원본 파일 그대로
Layer 1: Parsed    → 파일에서 추출한 구조화 데이터 (플랫폼 종속 스키마)
Layer 2: Clean     → 표준 스키마로 변환 + 마스킹 + 품질 검증 완료
Layer 3: Analytics → 분석 결과 (실질 수수료율, 광고 ROI, 메뉴 수익성 등)
```

## 2. 레이어별 상세

### Layer 0: Raw (원본)

| 항목 | 설명 |
|---|---|
| 내용 | 사장님이 업로드한 엑셀/CSV/PDF 파일 원본 |
| 저장소 | 암호화 파일 스토리지 (AES-256) |
| 보관기간 | 업로드 후 90일 |
| 용도 | 파서 버그 수정 후 재파싱, 정산 검증 증빙 |
| 접근 권한 | 사장님(다운로드), 시스템(파싱/삭제) |
| 메타데이터 | raw_data 테이블 (file_hash, file_size, storage_path) |

### Layer 1: Parsed (파싱)

| 항목 | 설명 |
|---|---|
| 내용 | 파일에서 추출한 행/컬럼 데이터 (플랫폼 원본 필드명 유지) |
| 저장소 | DB (parsed_* 스테이징 테이블) |
| 보관기간 | Layer 2 변환 완료 후 30일 |
| 용도 | 파싱 결과 검증, 매핑 오류 추적 |
| 접근 권한 | 시스템만 |
| 특징 | 플랫폼 종속 스키마. 배민 파서 결과와 쿠팡이츠 파서 결과의 컬럼명이 다를 수 있음 |

### Layer 2: Clean (정제)

| 항목 | 설명 |
|---|---|
| 내용 | 표준 스키마로 변환 + 개인정보 마스킹 + 품질 검증 완료 데이터 |
| 저장소 | DB (settlements, orders, ads, menus, daily_metrics 등) |
| 보관기간 | 서비스 이용 기간 (탈퇴/철회 시 30일 내 삭제) |
| 용도 | 분석 엔진 입력, 리포트 생성, 벤치마크 집계 |
| 접근 권한 | 사장님(리포트 경유), 시스템(분석) |
| 특징 | 플랫폼 중립 스키마. fee_type 등 표준 코드 사용 |

### Layer 3: Analytics (분석)

| 항목 | 설명 |
|---|---|
| 내용 | 실질 수수료율, 광고 ROI, 메뉴별 수익성, 전월 대비 변화 등 계산 결과 |
| 저장소 | DB (report_* 테이블) 또는 캐시 |
| 보관기간 | 서비스 이용 기간 (리포트 재생성 가능) |
| 용도 | 사장님 리포트 표시, 이상징후 알림 |
| 접근 권한 | 사장님(직접 조회/다운로드) |
| 특징 | Layer 2에서 언제든 재계산 가능 |

## 3. 처리 흐름

```
[사장님 업로드]
    │
    ▼
Layer 0: Raw ─── 원본 저장 (암호화)
    │
    ▼
[파서 실행] ─── 플랫폼별 파서 선택 (baemin_parser, coupangeats_parser...)
    │
    ▼
Layer 1: Parsed ─── 구조화 추출 + 기본 유효성 검사
    │
    ▼
[마스킹/변환] ─── 개인정보 마스킹 + 표준 스키마 매핑 + 품질 검증
    │
    ▼
Layer 2: Clean ─── 정제 데이터 저장
    │
    ▼
[분석 엔진] ─── 실질 수수료율, ROI, 수익성, 전월비교 계산
    │
    ▼
Layer 3: Analytics ─── 리포트 생성
```

## 4. 재처리 시나리오

| 시나리오 | 재처리 범위 | 트리거 |
|---|---|---|
| 파서 버그 수정 | Layer 0 → Layer 1 → 2 → 3 재실행 | 개발팀 배포 |
| 매핑 테이블 변경 | Layer 1 → Layer 2 → 3 재실행 | 수수료 항목 추가/변경 |
| 분석 로직 변경 | Layer 2 → Layer 3 재실행 | 계산식 수정 |
| 마스킹 규칙 추가 | Layer 1 → Layer 2 재실행 | 개인정보 패턴 추가 |

> Layer 0 원본이 있으면 모든 레이어를 처음부터 재생성할 수 있다.
> 원본 보관기간(90일) 이후에는 Layer 2부터만 재처리 가능하다.

## 5. 스테이징 테이블 (Layer 1)

Layer 1은 플랫폼별 임시 테이블로 관리한다.

```
parsed_baemin_settlements   → 배민 정산 파싱 결과
parsed_baemin_sales         → 배민 매출 파싱 결과
parsed_baemin_ads           → 배민 광고 파싱 결과
parsed_baemin_menus         → 배민 메뉴 파싱 결과
```

Layer 2 변환 완료 후 30일간 보관하고 삭제한다.
