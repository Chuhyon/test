# 데이터 보관·삭제 정책 (T008)

## 목적

원본 파일, 정제 데이터, 리포트 데이터의 보관기간과 삭제 프로세스를 정의한다.

## 1. 데이터 유형별 보관 정책

| 데이터 유형 | 설명 | 보관기간 | 삭제 방식 | 저장소 |
|---|---|---|---|---|
| **원본 파일** | 사장님이 업로드한 엑셀/CSV | 업로드 후 90일 | 자동 삭제 (배치) | 암호화 파일 스토리지 |
| **정제 데이터** | 파싱 후 표준화된 정산/매출 데이터 | 서비스 이용 기간 | 탈퇴/철회 시 30일 내 삭제 | 암호화 DB |
| **리포트 데이터** | 생성된 분석 리포트 | 서비스 이용 기간 | 탈퇴/철회 시 30일 내 삭제 | 암호화 DB |
| **벤치마크 집계** | 익명화된 업종/지역 통계 | 갱신 주기까지 | 다음 갱신 시 제외 | 집계 DB |
| **감사 로그** | 접근/처리/삭제 이력 | 3년 | 보관기간 후 삭제 | 별도 로그 DB |
| **사장님 계정 정보** | 이름, 연락처, 사업자번호 | 서비스 이용 기간 | 탈퇴 시 30일 내 삭제 | 암호화 DB |

## 2. 관계법령에 따른 최소 보관 기간

| 법령 | 보관 대상 | 기간 |
|---|---|---|
| 전자상거래법 제6조 | 계약/청약철회 기록 | 5년 |
| 전자상거래법 제6조 | 대금결제/재화공급 기록 | 5년 |
| 전자상거래법 제6조 | 소비자 불만/분쟁처리 기록 | 3년 |
| 통신비밀보호법 제15조의2 | 서비스 이용 기록 | 3개월 |
| 국세기본법 제85조의3 | 세무 관련 증빙 | 5년 |

> 법령 보존 기간이 본 정책보다 긴 경우, 법령 기간을 우선 적용한다.
> 법령 보존 대상 데이터는 별도 분리 보관하며, 해당 목적 외 이용을 금지한다.

## 3. 삭제 시나리오

### 3.1 정상 보관기간 만료 (자동)

```
[매일 배치 실행]
  → 원본 파일 중 업로드 후 90일 경과 항목 식별
  → 파일 삭제 + 메타데이터(file_hash, uploaded_at) 삭제
  → audit_logs에 삭제 기록
```

### 3.2 사장님 동의 철회 (요청)

```
[사장님 철회 요청]
  → 철회 범위 확인 (전체 / 특정 데이터 범위)
  → 30일 내 삭제 처리 시작
    ├─ 원본 파일 삭제
    ├─ 정제 데이터 삭제
    ├─ 리포트 데이터 삭제
    ├─ 벤치마크 집계에서 제외 (다음 갱신 시)
    └─ 감사 로그에 삭제 기록 (삭제 이력 자체는 3년 보관)
  → 사장님에게 삭제 완료 통지
```

### 3.3 서비스 탈퇴 (요청)

```
[사장님 탈퇴 요청]
  → 전체 동의 철회와 동일하게 처리
  → 추가로 사장님 계정 정보 삭제
  → 법령 보존 대상 데이터는 별도 분리 보관
  → 탈퇴 완료 통지
```

### 3.4 가게 양도/폐업

```
[사장님 가게 양도/폐업 통보]
  → 해당 store_id 관련 모든 데이터 동결
  → 사장님에게 데이터 삭제 또는 이관 선택 요청
  → 30일 내 미응답 시 전체 삭제
```

## 4. 삭제 방식

| 데이터 유형 | 삭제 방법 | 검증 |
|---|---|---|
| 파일 스토리지 | 파일 삭제 + 덮어쓰기 | 삭제 후 접근 불가 확인 |
| DB 레코드 | DELETE + 물리 삭제 확인 | 소프트 삭제 금지 (실제 삭제) |
| 백업 | 다음 백업 주기에 제외 | 이전 백업에 포함된 데이터는 백업 보관기간 만료 시 삭제 |
| 로그 | 보관기간 만료 시 삭제 | 삭제 이력 자체는 audit_logs에 기록 |

## 5. 접근 제어

| 역할 | 원본 파일 | 정제 데이터 | 리포트 | 감사 로그 |
|---|---|---|---|---|
| 사장님 (본인) | 다운로드 가능 | 리포트로 조회 | 조회/다운로드 | 본인 이력만 |
| 서비스 운영자 | 접근 불가 (원칙) | 집계 통계만 | 접근 불가 | 전체 조회 |
| 시스템 (배치) | 삭제용 접근 | 분석용 접근 | 생성용 접근 | 기록용 접근 |
| 외부 제3자 | 접근 불가 | 접근 불가 | 접근 불가 | 접근 불가 |

> 운영자가 개별 가게 데이터에 접근해야 하는 경우 (장애 대응 등),
> 사전 사유 기록 + 사후 감사 로그 확인 절차를 거친다.
