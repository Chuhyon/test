# 데이터 품질 검증 룰 (T014)

## 목적

파싱 및 정제 과정에서 데이터 오류를 감지하고,
잘못된 리포트가 발행되지 않도록 품질 게이트를 정의한다.

## 1. 검증 레벨

| 레벨 | 시점 | 실패 시 동작 |
|---|---|---|
| L1: 파일 검증 | 업로드 직후 | 업로드 거부 + 사장님 안내 |
| L2: 파싱 검증 | Layer 0 → Layer 1 | 파싱 중단 + 오류 항목 표시 |
| L3: 정합성 검증 | Layer 1 → Layer 2 | 경고 표시 + 수동 확인 요청 |
| L4: 분석 검증 | Layer 2 → Layer 3 | 이상값 표시 + 리포트에 주석 |

## 2. L1: 파일 검증 룰

| 룰 ID | 검증 항목 | 조건 | 실패 시 |
|---|---|---|---|
| L1-01 | 파일 형식 | xlsx, xls, csv만 허용 (PDF는 향후) | 거부: "지원되지 않는 파일 형식입니다" |
| L1-02 | 파일 크기 | 50MB 이하 | 거부: "파일이 너무 큽니다 (최대 50MB)" |
| L1-03 | 파일 중복 | file_hash 기준 동일 파일 재업로드 | 경고: "이미 업로드된 파일입니다" |
| L1-04 | 악성 파일 | 매크로/스크립트 포함 여부 | 거부: "보안 검증을 통과하지 못했습니다" |
| L1-05 | 빈 파일 | 데이터 행 0건 | 거부: "데이터가 없는 파일입니다" |

## 3. L2: 파싱 검증 룰

| 룰 ID | 검증 항목 | 조건 | 실패 시 |
|---|---|---|---|
| L2-01 | 필수 컬럼 존재 | 파일 유형별 필수 컬럼 확인 | 파싱 중단: "필수 항목이 누락되었습니다: [컬럼명]" |
| L2-02 | 날짜 형식 | 날짜 필드가 유효한 날짜인가 | 해당 행 스킵 + 오류 카운트 |
| L2-03 | 금액 형식 | 금액 필드가 숫자인가 | 해당 행 스킵 + 오류 카운트 |
| L2-04 | 음수 금액 | 매출/주문금액이 음수인가 | 경고: 취소/환불인지 확인 |
| L2-05 | 날짜 범위 | 미래 날짜 또는 5년 이전 | 경고: "날짜 범위를 확인해 주세요" |
| L2-06 | 파싱 성공률 | 전체 행 중 파싱 성공 비율 | 80% 미만이면 경고 표시 |

## 4. L3: 정합성 검증 룰

| 룰 ID | 검증 항목 | 조건 | 실패 시 |
|---|---|---|---|
| L3-01 | 정산 합계 검증 | 총주문금액 - 총차감액 = 실입금액 (±100원) | 경고: "정산 합계가 일치하지 않습니다" |
| L3-02 | 수수료율 범위 | 실질 수수료율이 0~50% 범위 | 경고: "수수료율이 비정상적입니다" |
| L3-03 | 일별 매출 연속성 | 연속 7일 이상 매출 0원 | 경고: "영업 중단 기간이 포함되어 있습니다" |
| L3-04 | 기간 중복 | 동일 기간 정산 데이터 중복 업로드 | 경고: "이미 등록된 기간의 데이터입니다" |
| L3-05 | 주문수-매출 비례 | 주문수 × 평균단가와 매출의 차이가 50% 이상 | 경고: "주문수와 매출이 크게 차이납니다" |
| L3-06 | 광고비-매출 비율 | 광고비가 매출의 30% 초과 | 경고: "광고비 비율이 매우 높습니다 (확인 필요)" |
| L3-07 | 수수료 항목 합산 | 개별 수수료 항목 합계 = 총 차감액 (±100원) | 경고: "수수료 항목 합계가 일치하지 않습니다" |

## 5. L4: 분석 검증 룰

| 룰 ID | 검증 항목 | 조건 | 실패 시 |
|---|---|---|---|
| L4-01 | 전월 대비 급변 | 매출/수수료율이 전월 대비 50% 이상 변동 | 리포트에 "큰 변동이 감지되었습니다" 표시 |
| L4-02 | 이상치 감지 | 일별 매출이 평균의 3배 이상 또는 1/3 이하 | 리포트에 해당일 하이라이트 |
| L4-03 | 광고 ROI 음수 | 광고 경유 매출 < 광고비 | 리포트에 "광고 효과를 재검토하세요" 표시 |
| L4-04 | 메뉴 마진 음수 | 원가 입력 시 마진이 음수 | 리포트에 "원가가 판매가보다 높습니다" 표시 |

## 6. 오류 처리 정책

### 6.1 파싱 실패 시

```
파싱 실패 행수 < 전체의 20%
  → 성공 행만으로 리포트 생성 + 실패 행 수 표시
  → "일부 데이터(N건)를 읽지 못했습니다"

파싱 실패 행수 ≥ 전체의 20%
  → 리포트 생성 중단
  → "파일 형식이 맞는지 확인해 주세요"
  → 사장님에게 재업로드 또는 지원 요청 안내
```

### 6.2 정합성 경고 시

```
경고 항목이 있어도 리포트는 생성한다.
단, 경고 항목에 대해 리포트 내에 명확히 표시한다.

예시:
  ⚠ 정산 합계가 127원 차이납니다.
    배민 정산 기준과 소수점 반올림 차이일 수 있습니다.
```

### 6.3 사장님 안내 메시지

| 상황 | 메시지 |
|---|---|
| 파일 형식 오류 | "엑셀(.xlsx) 또는 CSV 파일만 업로드할 수 있습니다" |
| 필수 컬럼 누락 | "정산내역 파일이 맞는지 확인해 주세요. [항목명]이 없습니다" |
| 기간 중복 | "2024년 3월 정산 데이터가 이미 등록되어 있습니다. 덮어쓸까요?" |
| 파싱 부분 실패 | "123건 중 15건을 읽지 못했습니다. 나머지 108건으로 리포트를 만들까요?" |
| 정합성 경고 | "정산 합계에 차이가 있습니다. 리포트의 ⚠ 표시를 확인해 주세요" |
